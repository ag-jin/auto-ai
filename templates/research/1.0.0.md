# 调研交付

适用于技术调研、方案比较和设计探索。

## 主会话安排

1. 明确要支持的决定、研究范围和交付形式，归一化 Issue 输入。
2. 固定模板引用、要求版本与执行标识，将执行包交给 Worker。

## Worker 执行

1. 先阅读已有资料，将已知事实、待验证假设和影响决定的问题列清楚。
2. 围绕关键问题收集证据。可变信息核对当前状态，优先使用原始资料与官方来源。
3. 比较可行选项，说明取舍、适用条件和仍未解决的问题。
4. 将结论写入可独立阅读的产物，附来源、验证时间和证据限制；无法核实的信息明确标记。
5. 设计与规划交付必须收敛出 Execution Route：接下来做什么、需要什么输入、怎样验收。

## 主会话核验与交付

- 检查是否回答原问题，关键结论是否有相应证据，交付是否满足验收要求。
- 区分已验证事实与建议；调研结论不能表述成已实施或已运行的能力。
- 更新 Issue，关联报告；需要用户决定时给出具体选项及其影响。

## 统一返回格式

使用 `summary`、`artifacts`、`evidence`、`blockers`，并附 `run_id`、`attempt`、`requirements_rev`、`template_ref`。含义与开发模板一致。
