# 实际 Runtime 的界面闭环验收

日期：2026-11-18。作用于独立命名的双仓库测试数据，不是正式 `.auto-ai/app/`，没有批准真实功能 Issue 或合并真实 PR。

## 核验范围

- 实际生产前端、HTTP、Runtime、Workflow、WorkspaceAdapter。
- 真实临时 Git 仓库、独立 worktree/分支、提交、推送和回收。
- GitHub 与 Pi 为显式注入替身；真实 Pi 已在另一条独立脚本闭环重新核验 6/6，不能与本界面场景混称。
- 原生点击/按键通道没有触发独立 HTML 按钮，文本填充有效；桌面交互服务也不可用。已用原生按钮探针排除产品代码，并保留失败证据。
- 之后通过同一 CUA 浏览器文档允许的 CDP 能力激活 DOM 控件，填写实际表单、触发其事件处理器；没有直接调用前端私有对象或伪造后端授权数据。以下是 DOM 事件驱动的浏览器验收，不是原生输入通道验收。

## 实际通过的行为

1. 界面收集两个仓库的 6 条观测，5 条命中、1 条排除，未确认开发时没有 Worker。
2. 有待决策项时确认按钮禁用；编辑后未保存仍禁用；保存新 rev 后可确认。
3. 无稿整理进行中，分别点击忽略/暂缓；随后释放迟到整理结果，决定、状态和无稿状态都保持，结果记录 discarded。
4. 确认两个仓库任务后自动领取，实际生成两棵独立 Git 工作树；同仓冲突且跨仓依赖未完成的第三项任务保持队列，展示依赖、并发和写入冲突原因。
5. 单个执行替身失败后另一任务继续，界面显示阻塞；通过重试入口产生新 Run，不重新批准或丢失原授权。
6. 两个成功交付的文件均从临时远端 Git 独立读回，精确为 `ui-smoke`；两棵成功工作树在验收前已实际回收。
7. 两个结果进入 PR 验收；缺少结论时不能合并；设计说明为空时不能提交设计通过。
8. 用户和设计结论分别绑定当前 head；两种结论齐全仍需独立勾选确认。选择 squash 后明确发起，合并替身仅调用一次。
9. pending 不冒充完成，刷新后仍禁重发。修复了刷新后错误显示默认 merge 的问题，持久 squash 方式已实际恢复。
10. 仅将替身只读状态改为 MERGED，后台核验后进入 completed；完成记录变为只读，展示匹配当前 PR/head 的 merge SHA，不再显示重复验收/合并按钮。
11. 仓库筛选将两个验收结果缩为一个，再恢复为两个。

## 复跑入口

```sh
node scripts/serve-ui-fixture.mjs
```

启动输出独立 URL、evidence 和 controlFile。它始终使用明确替身与临时 Git，生产 `npm start` 不引用此脚本。控制文件中的 completeDrafts、failRuns、completeRuns、mergeState 仅模拟外部完成/失败/合并读回；开发与验收决定仍从界面提交。

Ctrl-C 停止，保存状态与 Git bundle 后回收自建干净工作树；脏目录或未识别目录保留。已实际烟测正常关闭、失败工作树回收、未知目录保留保护，后者使用测试者创建的标记验证并在记录后单独清理。
