# T004：中文多仓库需求与执行工作台前端

执行者固定为 Pi：`deepseek-flash / high`。使用当前独立会话、worktree 和任务分支。目标由用户已确认的系统建设范围授权。

## 目标与完成条件

实现真实 HTTP Interface 的中文前端，覆盖规则配置、候选池、任务稿审阅、开发/暂缓/忽略、并行任务、队列/阻塞和 PR 验收/合并。产物为 `public/index.html`、`public/styles.css`、`public/app.js` 与 `docs/worker-trials/T004-result.md`。不实现后端、不修改其他文件、不提交 Git。

先读 AGENTS.md、docs/CONTEXT_CARD.md、docs/UI_PLAN.md 和 docs/HTTP_CONTRACT.md。视觉以 UI_PLAN 为准，数据/操作以 HTTP_CONTRACT 为准；冲突时报告具体问题。前端与后端并行实施，目前可能没有正在运行的 HTTP 服务。

## 技术与组织

使用原生 HTML/CSS/ES module JavaScript，无框架、打包器、CDN、外部字体或图标依赖。所有 API 使用同源 `/api/...`。启动时请求 state，写操作携带 token，正确处理错误和 409 冲突。

遵循 UI_PLAN 的三列工作台。可用简洁手绘 SVG 图标（内联、可访问），不要图表装饰、营销标语或虚构统计。真实动态值使用 textContent 或统一安全转义；链接仅允许 http/https，不能把 Issue/任务稿 HTML 当作页面代码。

## 必须可操作的内容

1. 顶部收集 Issue 与自动监督开关、连接/监督状态；仓库筛选在各视图生效。
2. 规则/仓库页：可增删多个 `{repo,localPath,baseRef}`，编辑所有筛选类别和 global/perRepo 上限，保存完整 settings。规则字段说明类别间 AND、列表内 OR；空仓库不收集。
3. 候选视图：列表显示来源仓库、标题、状态、匹配/排除原因，支持查看排除项。详情显示 Issue 文本与链接；无稿时可请求整理。
4. 任务稿编辑：goal、scope、acceptance、context、pendingDecisions、templateId、priority、dependsOn、writeScopes；数组用每行一项输入。保存后采用返回的 rev，不自行生成授权版本。
5. 三个决定按钮。开发需有已保存草稿、非空验收、无待决策项；点击以当前 rev 发起决定，成功后自动刷新，无额外“派发”步骤。暂缓/忽略也使用当前 rev。
6. 执行总览：按仓库展示活动 Worker、队列、优先级、依赖与冲突/阻塞原因，能查看进度事件和来源/模板/run 详情，提供运行取消与已阻塞任务重试。
7. PR 验收页：展示最新结果、实际证据与 PR；分别记录用户和设计监督对当前 head 的 approved/changes_requested，设计记录包含说明。合并前明确展示 PR、head、两种结论和合并方式；用户确认后才发送 merge。前端不自行补齐或伪造验收记录。
8. 事件与结果用可读摘要，必要详情可展开；不要把后端内部堆栈、模型推理或配置密钥显示在正常产品流程中。

## 状态与交互约定

- 生产界面没有假数据。无配置、无候选、连接失败都给出可执行提示。
- 2—3 秒轮询 state；同一时刻只发起一轮刷新。编辑中不覆盖未保存内容；版本变化或保存 409 时保留输入并明确提示重新核对。
- 请求期间禁用对应按钮，完成后恢复，错误保留在相关位置；不重复发起开发或合并。
- 语义化表单与标签、可见焦点、键盘可用、合理对比度、移动端可读，尊重减少动效设置。

## 实际验证与回报

运行 `node --check public/app.js`，检查所有页面结构、字段和端点与合同一致。若没有真实浏览器/服务，明确说明浏览器交互尚未验证，不伪称通过。主会话负责集成后浏览器验收。

结果文档记录改动、运行命令、通过/未验证事项、接口疑问和范围偏差。保持其他任务的源码和 Git 状态不变。
