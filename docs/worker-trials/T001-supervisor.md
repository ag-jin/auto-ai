## 任务稿中的有效做法与问题

1. 一个任务只交付可独立验收的模块，给出明确工作目录、源码范围与完成条件。
2. 完整输入/输出样例、规范化和错误合同，使实现与核验有共同标准。
3. 由主会话独立检查，而后以最小复现、期望行为和修改范围反馈，模型能够完成针对性返修。
4. 原稿“测试失败要非零退出”诱发了测试 Node 框架自身的无关工作；返修明确将证据聚焦到产品行为，减少额外步骤。
5. 模型发现当前文件已经修复时应说明差异、保留改动，再选择有证据的后续工作；监督者也必须核对真实进程和当前文件。

复用格式见 [WORKER_BRIEF.md](../WORKER_BRIEF.md)。上述细节由主会话补齐，用户入口仍然只需要目标与验收要求。
