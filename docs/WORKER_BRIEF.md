# Worker 任务稿格式 v1

用途：主会话向 Pi 派发一个可独立验收的工作单元。首个实测为 [T001](worker-trials/T001-task.md)，执行模型固定为 `deepseek-flash / high`。

## 六段任务稿

| 段落 | 写清什么 | 完成判断 |
| --- | --- | --- |
| 目标 | 本次要交付的一个具体结果，怎样才算完成 | 有可检查产物和验收证据 |
| 事实来源 | 工作目录、必读文件、按需参考与冲突时的权威来源 | Worker 可从文件恢复任务，不依赖主会话聊天历史 |
| 范围 | 允许改动的位置、技术选择、由谁提交与发布 | 可直接核对改动清单 |
| 接口合同 | 输入、输出、默认值、规范化、失败语义，以及一个完整样例 | 可用具体输入判断实现对错 |
| 验收 | 正常路径、关键失败路径、版本变化等实际场景 | 每条都有可执行检查或可观察结果 |
| 验证与回报 | 实际运行方式、证据位置、具体阻塞和未验证内容 | 主会话能够独立复跑 |

用户只需提供目标和验收要求；接口、文件范围与验证样例由主会话依据项目资料补齐。主会话先把关键选择收敛到可执行程度，Worker 负责范围内的实现细节。参考资料通过明确的读取条件提供，避免把整段聊天和无关历史塞进任务稿。

## 可复制骨架

```markdown
# <任务 ID>：<可验收结果>
版本：<任务稿版本>。执行者：Pi，deepseek-flash / high。

## 目标与完成条件
<本次结果与完成标准>

## 执行位置与事实来源
<目录、必读文件、按需参考、冲突处理>

## 范围
<允许改动的位置、必要技术约定、提交与发布职责>

## 输入与输出合同
<完整样例、默认值、规范化、错误行为>

## 验收样例
<正常路径与关键边界，每项对应可检查结果>

## 执行与回报
<实际命令、证据位置；summary / artifacts / evidence / blockers>
```

## 返修稿

提供“已复现的输入 → 实际错误行为 → 期望行为 → 修改范围 → 回归要求”，引用原合同，不改写整项任务。实际样例见 [T001 返修 1](worker-trials/T001-fix-1.md)。

独立验收发现新的失败后，保留最小复现并补为回归。验收尚未通过时，主会话继续安排修复；成功与失败的记录均保留。

## 迭代依据

每次试跑记录任务稿版本、实际模型与思考档位、耗时、范围偏差、首次交付结果、独立验收发现和返修次数。区分模型实现失误、任务稿遗漏和环境问题，按原因改进。

任务专属的接口细节留在任务稿与测试里；只有能跨任务复用的方法才进入执行模板。单个样例通过只能说明这类任务在本次配置下可完成，不能推定完整系统已被验证。
