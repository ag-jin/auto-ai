# 前端设计计划

使用场景：一个人管理多个仓库的需求与并行执行，最重要的动作是看清任务稿、作出开发决定、发现阻塞和逐个验收 PR。

## 视觉与布局

- 基底 `#F5F7FA`、表面 `#FFFFFF`、正文 `#1C2D41`、导航 `#17233A`、操作青 `#087E8B`、结构线 `#D4DDE6`；阻塞琥珀与错误红仅用于状态。
- 中文使用本机 PingFang SC / Noto Sans CJK SC；标题 22px、分区 17px、正文 14px，日志/commit 使用等宽字体。无需网络字体。
- 桌面采用三列工作台：窄导航与仓库筛选、候选列表、任务稿/进展审阅；执行总览与规则页使用完整内容宽度。窄屏按导航、列表、详情顺序收敛。

```text
┌────────────┬──────────────────────────────────────────────────────┐
│ auto-ai    │ 当前仓库范围                 收集 Issue  自动监督     │
│            ├──────────────────┬───────────────────────────────────┤
│ 全部仓库   │ 候选需求列表     │ 目标、范围、验收、待决策事项       │
│ 仓库筛选   │ 状态与命中原因   │ 开发 / 暂缓 / 忽略                 │
│            │                  │ 进展、证据、PR 与逐项验收          │
│ 需求 / 执行│                  │                                   │
│ 验收 / 规则│                  │                                   │
└────────────┴──────────────────┴───────────────────────────────────┘
```

## 对照目标后的收敛

不采用营销首屏或重复大卡片。重点放在任务内容和当前决定，数量只作为列表、仓库总览和队列的辅助信息。动态刷新保持用户正在编辑的文本，避免以频繁重绘打断审阅。

功能上完整覆盖：多仓库配置与筛选、规则、命中/排除原因、任务稿版本与编辑、用户决定、并行 Run、优先级/依赖/冲突原因、阻塞与重试、PR 双重验收及明确合并。

前端负责清楚呈现和显式操作，后端是授权与调度的权威。当前 HTTP 合同见 `HTTP_CONTRACT.md`。
